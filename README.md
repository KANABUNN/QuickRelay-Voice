# QuickRelay Voice

QuickRelay Voice（QRV）は、QuickRelay の緊急地震速報（EEW）を Windows で受信し、AivisSpeech で読み上げるアプリです。警報、警報地域の追加、予報の各報、最終報、明示取消を読み上げます。続報は前に読み上げた内容との違いだけを伝えるため、地震モニターを見なくても音声だけで状況を追えます。配信の接続状態、上流と取込の状態、時刻差、音声合成、音声出力を画面で確認できます。

## 起動

公開フォルダーから起動する場合は、Windows x64 用の .NET 10 Desktop Runtime を入れ、`QuickRelay Voice.exe` を実行します。開発環境からは .NET 10 SDK で実行できます。

```powershell
dotnet run --project .\QuickRelay.Voice\QuickRelay.Voice.csproj
```

1. AivisSpeech を起動します。QRV の既定ポートは `10101` です。「音声」タブでモデルとスタイルを選び、「テスト再生」で Windows の既定の音声出力を確認できます。モデルとスタイルの一覧は起動時と「音声」タブを開いたときに取得し、「一覧を取得」で取り直せます。モデルを「自動」にすると最初のモデルを、スタイルを「自動」にすると選んだモデルの「ノーマル」スタイルを優先します。
2. 「接続」タブで QuickRelay EEWブリッジの `wss://ホスト/v1/eew` と端末用 Bearer トークンを指定します。PR-Cのサーバーが提供する配信環境は `production` です。上部の「消音」は新規設定時に有効です。配信の初回確認は消音のまま画面下の「保存して接続」を選び、同期完了と上流・取込の状態を「状態」タブで確認します。「保存して接続」はすべてのタブの設定を保存します。
3. 「範囲」タブで読み上げる範囲を設定します。警報の対象は既定で全国です。「全国の警報を対象にする」を外すと、対象地域に絞れます。地域欄には配信側で定義された `codeType:code` を1行に1件入力します。予報の読み上げは既定で無効です。有効にすると最低震度を設定できます。最低震度は地震を読み上げ始める条件で、一度読み上げた地震は最終報まで、震度が下がった報も含めて読み上げます。「震度0」はすべての地震が対象です。

### 読み上げの内容

予報と警報の電文を受けるたびに読み上げます。震源の推定精度やマグニチュードの計算に使った観測点の数では絞り込みません。読み上げる文は再生する直前に、その地震の最新の状態と前に読み上げた内容を比べて決めます。読み上げ中に続報が何件か届いても、次は最新の報を1回だけ読み上げます。

| 場面 | 読み上げの例 |
| --- | --- |
| 予報の第1報 | 緊急地震速報、予報、第1報。石川県能登地方で地震、予想最大震度3、マグニチュード3.5、深さ10キロ。 |
| 続報 | 第2報。予想最大震度4に上昇、マグニチュード3.8に上昇。 |
| 最終報 | 第5報、最終報。石川県能登地方で地震、予想最大震度4、マグニチュード3.7、深さ20キロ。 |
| 警報 | （固定の警報音声）対象地域は、石川です。 |
| 警報地域の追加 | 第3報。警報地域追加、富山、新潟、福井、岐阜、長野、ほか1地域。 |
| 取消 | 先ほどお伝えした石川県能登地方の緊急地震速報は取り消されました。 |

- 続報では、変わった項目だけを「上昇」「低下」「変更」を付けて伝えます。対象は震源、予想最大震度、マグニチュード、深さ、長周期地震動階級（1以上のとき）、地域を絞っている場合はその地域の予想震度です。変化のない続報は読み上げず、最近の動作欄に理由を表示します。最終報は全項目を読み上げます。
- 仮定震源（PLUM法など）の報には「震源は仮定」、1点観測の報には「1点観測」と付けます。その後の報で震源が推定されたときは「震源は〇〇と推定」、観測点が増えたときは「震源精度向上」と伝えます。
- 地名は、AivisSpeech が読み違える部分を既定の読みに置き換えてから渡します（例：渡島 → オシマ、後志 → シリベシ、中越 → チュウエツ）。置き換えるのは震源名と地域名だけで、報番号や数値には使いません。読みの追加と変更は、下の `readings.json` でできます。
- 警報地域は府県予報区の名前で読みます。同じ報に含まれる地方予報区と細分区域の名前は重ねて読みません。6件以上のときは5件の後に残りの件数を読みます。府県予報区が含まれない追加は、細分区域または地方予報区の名前で読みます。
- 新規警報では、固定の警報音声を再生している間に対象地域の文を合成し、警報音声の直後に続けます。警報音声が終わってから0.75秒以内に合成が終わらないときは、対象地域を省き、最近の動作欄に表示します。
- 別の地震を読み上げた後に続報を読むときは、「石川県能登地方の地震、第4報。」のように震源名から始めます。
- 予報より警報を優先します。警報が予報の読み上げを中断した場合、中断された報は警報の後で、前に読み上げた内容と比べて改めて読み上げます。

### 音声パラメーター

「音声」タブで、AivisSpeech の音声合成クエリに渡す値を設定できます。範囲は AivisSpeech Engine の API 仕様に合わせています。

| 項目 | AudioQuery | 範囲 | 既定値 |
| --- | --- | --- | --- |
| 話速 | `speedScale` | 0.50〜2.00 | 1.08 |
| 感情表現 | `intonationScale` | 0.00〜2.00 | 1.00 |
| テンポの緩急 | `tempoDynamicsScale` | 0.00〜2.00 | 1.00 |
| 音高 | `pitchScale` | -0.15〜0.15 | 0.00 |
| 音量 | `volumeScale` | 0.00〜2.00 | 1.00 |
| 句読点の間 | `pauseLengthScale` | 0.00〜2.00 | 1.00 |
| 前の無音 (秒) | `prePhonemeLength` | 0.00〜1.50 | 0.10 |
| 後の無音 (秒) | `postPhonemeLength` | 0.00〜1.50 | 0.10 |

感情表現はノーマルスタイルでは自動で調整されるため、エンジン側で使われません。音高を 0.00 から変えると音質が下がることがあります。前の無音を長くすると、警報の出音もその分遅れます。音量は内蔵の警報音にも適用します。エンジンが返さない項目は送りません。

「音声設定を保存」は配信に接続したままでも使えます。接続中は、再生中の音声を前の設定のまま終え、次の読み上げから新しい設定を使います。固定の警報音声は新しい設定で準備し直し、準備が終わるまでの新規警報には内蔵の非言語音を使います。保存したスタイルがエンジンから消えた場合は、同じモデル内の同名スタイル、次にモデルの最初のスタイルを使います。

### タスクトレイ

QRV はタスクトレイにアイコンを表示します。アイコン右下の色は、緑が読み上げ可能、黄が消音または接続準備中、赤が異常、灰色が未接続です。アイコンをクリックするとウィンドウを表示し、右クリックのメニューから消音、再生停止、終了を選べます。

「常駐」タブで次の動作を設定できます。設定は変更した時点で保存します。

- 最小化・閉じるボタンでタスクトレイに格納する（既定で有効）。無効にすると、閉じるボタンで終了します。
- 起動時はウィンドウを開かずタスクトレイに格納する。
- 起動時に保存済みの配信先へ接続する。保存済みのトークンがある場合に接続します。

同じタブの「スタートアップに追加」で、Windows にサインインしたときに QRV を起動できます。管理者権限は不要で、もう一度押すと削除します。起動後の動作は上の「起動時」の設定に従うため、サインイン時に画面を出さずに受信を始めるには、トレイへの格納と自動接続もオンにします。登録はタスクマネージャーの「スタートアップ」に表示され、そこで無効にした場合は画面にその旨を表示します。QRV を別のフォルダーへ移した場合は「この場所で登録し直す」を押します。

QRV は1台につき1つだけ起動します。起動中にもう一度起動すると、起動中のウィンドウを前面に表示します。

消音中も状態を更新し、読み上げる文を「無音検証」として最近の動作欄に表示します。消音中は読み上げた記録が残らないため、続報も全項目の文で表示します。消音を解除すると、その後に成立した候補から判定します。同期中や接続先の上流・取込・時刻に異常がある場合は音声を保留します。再接続時のスナップショットと再送は、明示取消を含めて無音で適用します。QRV がすでに報知した系列のライブ取消は、開始期限内に条件がそろえば一度読み上げます。

### 遅延の記録

配信で届いた報ごとに、QuickRelay が電文を受信してから QRV が受け取るまでの時間を最近の動作欄に表示します。

```text
19:12:03　（地震ID）　VXSE45　第3報　更新　位置 1234　VPS受信→QRV受信 41 ms（VPS内 23 ms・配信 18 ms）
19:12:04　音声開始　（地震ID）　予報　発表から 1210 ms　QRV受信から 655 ms
```

- VPS内：電文の受信（`receivedAt`）から配信内容の確定（`committedAt`）まで。どちらも VPS の時計で測ります。電文によらない更新では表示しません。
- 配信：確定から QRV が受け取るまで。PC の時計は使いません。QuickRelay が5秒ごとに送る死活通知は送信直前の VPS の時刻を持つため、その到着時刻と比べます。直近5分で最も速く届いた死活通知を基準にするので、回線の片道の最小遅延（VPS との往復時間の半分ほど）は含みません。接続し直すと基準を測り直し、最初の死活通知が届くまでは「配信」を表示しません。
- QRV受信から：その地震の最後の報を受け取ってから音声が出始めるまで。待ち行列、音声合成、出力機器の準備を含みます。「発表から」は気象庁の発表時刻（秒単位）からの時間です。

## ビルドと確認

リポジトリのルートで実行します。

```powershell
dotnet build .\QuickRelay.Voice\QuickRelay.Voice.csproj -c Release
dotnet run --project .\QuickRelay.Voice.Checks\QuickRelay.Voice.Checks.csproj -c Release
dotnet publish .\QuickRelay.Voice\QuickRelay.Voice.csproj -c Release -r win-x64 --self-contained false -o .\artifacts\publish
& '.\artifacts\publish\QuickRelay Voice.exe'
```

`QuickRelay.Voice.Checks` は、QuickRelay PR #18に含まれる正式な配信例6件と、ローカルの TLS WSS フィクスチャを使います。購読、警報地域の出典、予報の読み上げ文と差分、地名の読みの辞書、証明書検証、Bearer認証、同期と再開、クローズコード、発話条件、PC の時計によらない配信時間の計算を確認できます。AivisSpeech の応答を模したハンドラーで、音声パラメーターの送信、モデルとスタイルの選択、再生を待たない先行合成、0.2.0 の設定ファイルの読み込みも確認します。

### 地名の読みの確認

AivisSpeech のエンジンやモデルを更新したときは、地名の読みを確かめます。AivisSpeech を起動した状態で実行します。

```powershell
dotnet run --project .\QuickRelay.Voice.ReadingCheck -c Release > readings-check.tsv
```

`QuickRelay.Voice.ReadingCheck/place-names.txt` の名称を、エンジンの `/accent_phrases` に通します。辞書を通さない読みと、辞書で置き換えた名称の読みを、タブ区切りで出力します。アクセント句の区切りは `/` です。ポート、スタイル、`readings.json` は QRV の保存先から読み込み、`--port`、`--style <ID>`、`--readings <パス>` で変えられます。ほかの名称の一覧（1行に1件）を引数に渡すこともできます。同梱の一覧は、2026-11-27 に確かめた代表の約140件で、全件ではありません。読み違いが見つかったら、`PlaceReadings` の既定の読みか `readings.json` に足します。

## 保存先

- `%LOCALAPPDATA%\QuickRelay Voice\settings.json` に配信先、配信環境、対象地域、消音、予報、AivisSpeech のポート・モデル・スタイル・音声パラメーター、タスクトレイの設定を保存します。0.2.0 の設定ファイルはそのまま読み込み、追加の項目には既定値を使います。範囲外の音声パラメーターは既定値に戻します。
- 同じフォルダーの `feed-prc-*.json` に配信の再開位置と地震の状態を、`speech-*.json` に重複防止用の報知開始記録と、続報の差分の基準になる読み上げ済みの内容を保存します。以前の版の記録もそのまま読み込みます。0.1.0からの更新後は初回にスナップショットで同期し、報知開始記録を引き継ぎます。
- トークンは Windows 資格情報マネージャーの汎用資格情報 `QuickRelay Voice/<接続先・環境のハッシュ>` に保存します。
- スタートアップに追加すると、`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` に値 `QuickRelay Voice`（実行ファイルのパス）を登録します。
- 4410を受信したときは、失効済みトークンを識別するハッシュを `revoked-*.json` に保存します。アプリを再起動した場合も新しいトークンが必要です。
- 同じフォルダーに `readings.json` を置くと、地名の読みを追加・変更できます。JSON オブジェクトに `{"渡島":"おしま","例示地域":"れいじちいき"}` の形式で指定すると、次回接続時に読み込みます。キーは名称の一部でもよく、名称の中で一致した部分を置き換えます。重なるときは長いキーを優先し、既定の読みと同じキーは `readings.json` の指定で上書きします。空の読みや61文字以上の読みは使いません。

出力の直前に報知開始記録を保存します。記録後から実際の出音までに異常終了した場合は、再起動後の重複防止を優先するため、その音声が流れないことがあります。

## QuickRelay PR-C との接続

QuickRelay PR #18のマージコミット `bbea0b9` に含まれる正式なWSS v1契約に対応します。地域設定は `codeType` とコードの完全一致で判定します。予報は品質（`quality`）に関係なく読み上げます。予報の最終報は、`speechUntil` が `null` でも、発表から10秒以内の期限が付いていても受け付け、どちらも発表から10秒以内なら読み上げます。QuickRelay の配信は現在 `null` です。 [正式スキーマ](https://github.com/KANABUNN/QuickRelay/blob/bbea0b9380447db48f0885a5a027264cd5b40dd3/contracts/eew-wss.schema.json)

4409を受信すると保存カーソルを解除し、接続し直して全同期します。4410では自動再接続を止め、新しいトークンの入力を求めます。4400、4403、4413では購読、認可、上限エラーを表示して停止します。429では1分待ってから再接続します。 [QuickRelayのWSS運用資料](https://github.com/KANABUNN/QuickRelay/blob/bbea0b9380447db48f0885a5a027264cd5b40dd3/docs/eew-bridge.md)

ローカルの AivisSpeech Engine 1.1.0-dev で話者一覧、二段階の合成、固定音声のキャッシュ、Windows 出力の準備まで確認しました。VPS上の配信からWindowsの出音までの通し試験、聞き取り、警報開始と割り込み停止の実測 p95 は、配信を展開した環境と運用端末で確認する項目です。AivisSpeechが準備できていない場合、新規警報には内蔵の非言語音を使います。
